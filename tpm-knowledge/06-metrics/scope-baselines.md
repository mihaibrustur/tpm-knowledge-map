# Scope baselines and drift

Snapshotting what a sprint or release contained when it started, then comparing it with what actually shipped.

## Why it matters

Without a baseline, scope change is invisible and every slip looks like slow execution. With one, you can see what was added, removed or carried over, and talk about it honestly.

## Pitfalls

- Mixing defects found in release testing with new scope added late.
- Comparing sprint subtasks with release-level features as if they were the same unit.
- Taking the baseline after the first day's changes instead of at the start.
