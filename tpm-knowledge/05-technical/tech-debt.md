# Technical debt

Shortcuts in code or architecture that speed up delivery now and cost extra effort later.

## Why it matters

Some debt is a sensible trade-off. The TPM's job is to make it visible and make sure the cost is paid down deliberately rather than ignored.

## Pitfalls

- Treating all debt as bad, or all debt as acceptable.
- Debt that is never recorded, so it cannot be prioritized.
- No regular capacity set aside to pay it down.

## Reflect

- How did you make the case for paying down debt over new features?
